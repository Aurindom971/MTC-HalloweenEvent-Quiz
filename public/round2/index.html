Hosting Guide

To submit, you need two things:

  1. A live link that anyone can open: your website, put online with one of the hosts below.
  2. Your code: a GitHub repository link, or a .zip / Google Drive link.

Which host should we use?

All five are free and all work. Pick one:

🐙 GitHub Pages

Simplest if your code is already on GitHub. Link looks like username.github.io/project.

▲ Vercel

Clean link like project.vercel.app. Updates by itself every time you update GitHub.

💎 Netlify

You can just drag and drop your folder, no GitHub needed. Link like project.netlify.app.

⚡ Render

Connects to your GitHub repo. Link like project.onrender.com.

☁️ Cloudflare Pages

Upload your folder or connect GitHub. Link like project.pages.dev.

New to all this? Put your code on GitHub (the GitHub tab), then turn on GitHub Pages. That gives you both links. In a hurry? Drag your folder onto Netlify for the live link, and upload a .zip of your folder in the Submit form for the code.

Before you submit, check:

  • Your link opens on a phone that isn't on your laptop's Wi-Fi.
  • The design, images and buttons all load. Nothing should point to C:\Users\... on your laptop.
  • The link starts with https://.

Never used GitHub? No problem. Follow these steps in order: you'll send your project to GitHub with a few typed commands, then get a live link you can submit. Copy the commands exactly as shown.

The short version

  1. Make a free GitHub account
  2. Install Git on your laptop
  3. Create a new, empty public repository
  4. Open a terminal inside your project folder
  5. Push your code with a few commands
  6. Turn on GitHub Pages to get a live link

What is GitHub?

GitHub is like Google Drive, but for code. It stores your project online so judges can see it, and it can also turn your files into a real website for free.

Repository (repo)
A project folder on GitHub. One repo per project.
Terminal
A window where you type commands instead of clicking. Windows calls it Command Prompt; on a Mac it's called Terminal.
Commit
A save point of your files, with a short note about what changed.
Push
Sending your commits from your laptop up to GitHub.
GitHub Pages
GitHub's free hosting. It turns your repo into a live website link.

1 Create your account

  1. Go to github.com/signup.
  2. Enter your email, a password and a username. Your username appears in your website link, so keep it simple.
  3. Open the email GitHub sends you and enter the code to verify your account.

One account per team is enough. Whoever pushes the code can use their account.

2 Install Git

  • Windows: download Git from git-scm.com/downloads, run the installer and keep clicking Next. The default options are fine.
  • Mac: open Terminal (press Cmd+Space, type Terminal, press Enter), type git --version and press Enter. If Git isn't installed yet, your Mac offers to install it. Click Install.

To check it worked, open a terminal (step 4) and type git --version. You should see something like git version 2.47.0.

3 Create an empty repository

  1. On github.com click the + at the top right → New repository.
  2. Give it a name with no spaces, for example deadpool-job-board.
  3. Choose Public. Free hosting only works on public repos, and judges need to see your code.
  4. Leave everything else unticked: no README, no .gitignore, no license. The repo must be empty.
  5. Click Create repository and keep that page open. You'll need its link, which looks like https://github.com/your-username/deadpool-job-board.git

4 Open a terminal in your project folder

The terminal has to be “inside” your project folder: the folder that has your index.html in it. Pick whichever way suits you:

Windows, the quick way

  1. Open your project folder in File Explorer.
  2. Click the address bar at the top (where the folder's path is shown), type cmd and press Enter. A black window opens, already inside your folder.

On Windows 11 you can also right-click an empty space inside the folder and choose Open in Terminal.

Windows, typing the path

  1. Right-click your project folder and choose Copy as path (on Windows 10, hold Shift while you right-click). This copies the folder's path with quote marks around it.
  2. Open the Start menu, type cmd and open Command Prompt.
  3. Type cd /d (with a space at the end), paste the path with Ctrl+V, and press Enter. It looks like this: 
    cd /d "C:\Users\YourName\Desktop\my project"

Why the quote marks? If a folder name has a space in it (like my project), the terminal splits it in two without them. The /d lets it jump to another drive, such as D:.

Mac

  1. Open Terminal (Cmd+Space, type Terminal, press Enter).
  2. Type cd (with a space at the end), then drag your project folder from Finder into the Terminal window. Its path appears. Press Enter. It looks like this: 
    cd "/Users/yourname/Desktop/my project"

VS Code: open your project folder, then choose Terminal → New Terminal. It opens in the folder automatically.

Check you're in the right place: type dir (Windows) or ls (Mac) and press Enter. You should see index.html in the list.

5 Push your code (first time)

In that terminal, type these one at a time and press Enter after each. Put in your own name, email and repo link.

git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git init
git add .
git commit -m "first version"
git branch -M main
git remote add origin https://github.com/your-username/your-repo-name.git
git push -u origin main
  • The two git config lines tell Git who you are. You only need them once per laptop.
  • git add . picks up every file in the folder. The dot means “everything here”.
  • For git remote add origin, use your own repo link from step 3. Your empty repo's page on GitHub shows these exact commands with your link already filled in, under “…or push an existing repository from the command line”. You can copy them from there.
  • On the first push a window asks you to sign in to GitHub. Choose Sign in with your browser and approve it.

Now refresh your repo page on GitHub. All your files should be there. 🎉

6 Put it online with GitHub Pages

  1. In your repo, click Settings (top menu), then Pages (left menu).
  2. Under Build and deployment, set Source to Deploy from a branch.
  3. Set Branch to main and the folder to / (root), then click Save.
  4. Wait 1–3 minutes and refresh the page. A link appears at the top: https://your-username.github.io/your-repo-name/
  5. Open the link and check that your site works.

7 Changed something? Update it

  1. Save your files.
  2. Open a terminal in your project folder again (step 4).
  3. Run these three commands: 
    git add .
git commit -m "describe what you changed"
git push

That's it. GitHub updates straight away, and your live site within a minute or two. If you still see the old version, press Ctrl+Shift+R (Cmd+Shift+R on a Mac).

8 Submit your links

  • Live Hosted Website URL: your GitHub Pages link, https://your-username.github.io/your-repo-name/
  • GitHub Repository URL: the address of your repo page, https://github.com/your-username/your-repo-name

Common problems

“git is not recognized” / “command not found: git”

Git isn't installed yet, or the terminal was open while you installed it. Install Git (step 2), close the terminal, and open a new one.

“The system cannot find the path specified” / “no such file or directory”

The cd path has a typo or is missing its quote marks. Use Copy as path (Windows) or drag the folder into Terminal (Mac) so the path is exactly right, and keep the quotes.

“not a git repository”

The terminal isn't inside your project folder. Go back to step 4, then check with dir / ls that you can see index.html.

“Please tell me who you are” / “Author identity unknown”

Run the two git config --global lines from step 5, then run the git commit line again.

“src refspec main does not match any”

Nothing has been committed yet. Run git add . and git commit -m "first version", then git push -u origin main again.

“remote origin already exists”

You've already added a link. To replace it, run git remote set-url origin https://github.com/your-username/your-repo-name.git and push again.

Push “rejected” / “fetch first”

GitHub has something your laptop doesn't. This usually means a README was ticked when the repo was created, or a teammate pushed. Run this, then push again:

git pull --no-rebase --no-edit --allow-unrelated-histories origin main
git push
On a Mac, it asks for a password and won't accept mine

GitHub doesn't accept your normal password in the terminal. On github.com go to Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token (classic), tick repo, generate it and copy it. Paste that token when the terminal asks for the password. Nothing shows on screen while you paste or type the password. That's normal.

My link says “404: There isn't a GitHub Pages site here”

Wait 2–3 minutes and refresh. Check that your main file is named exactly index.html (all lowercase) and is at the top of the repo, that Pages is set to main and / (root), and that the repo is Public.

All my files are inside one folder in the repo

The terminal was opened one folder too high. Open it in the folder that directly contains index.html, and push from there.

My site loads but the design or images are missing

GitHub cares about capital letters: Logo.png and logo.png are different files, so the name in your code must match exactly. Use paths like images/logo.png, never C:\Users\....

I pushed a huge node_modules folder

Create a file called .gitignore in your project folder containing the line node_modules/, then run git rm -r --cached node_modules, commit and push again.

I really can't get the terminal working

As a last resort, on your repo's page click uploading an existing file (or Add file → Upload files), drag in the files inside your project folder, not the folder itself, and click Commit changes. Or ask an organiser to help you with the terminal.

How do I make a .zip of my project?

Windows: right-click your project folder → Compress to ZIP file (or Send to → Compressed (zipped) folder). Mac: right-click the folder → Compress.

Do we have to pay for anything?

No. A GitHub account, public repos and GitHub Pages are all free.

Your code is on GitHub (the tab, steps 1–5). This is how you keep it up to date while you build, and how to work on it as a team.

Three words you'll see

  • Commit: save a snapshot of your files, with a short note like “added the map”.
  • Push: send your commits from your laptop up to GitHub.
  • Pull: bring down changes a teammate pushed, so you have their work too.

The routine is always: save your files → commit → push.

1 Open a terminal in your project folder

Same as before: on Windows, type cmd in the File Explorer address bar of your project folder; on a Mac, type cd and drag the folder into Terminal; in VS Code, use Terminal → New Terminal. If you get stuck, see .

2 Commit and push

git add .
git commit -m "describe what you changed"
git push
  • Do this every time you finish a piece of work. Little and often is safer than one giant push at the end.
  • Good notes are short and say what changed: added the incident map, fixed the mobile menu, new colours.
  • “nothing to commit, working tree clean” means nothing has changed since your last commit. Did you save your files?

3 Working as a team

  1. The repo owner adds teammates: on github.com open the repo → Settings → Collaborators → Add people. Each teammate accepts the email invite.
  2. A teammate gets the code once, in a terminal: 
    git clone https://github.com/owner-username/your-repo-name.git
cd your-repo-name
  3. Always pull before you start working, so you have everyone's latest changes: 
    git pull
  4. When you're done, commit and push as in step 2.

Try not to edit the same file at the same time as a teammate. It saves a lot of headaches.

Prefer buttons to typing?

GitHub Desktop (an app, no commands)
  1. Install GitHub Desktop and sign in to GitHub.
  2. File → Add local repository… → choose your project folder. If it says it isn't a repository yet, click create a repository.
  3. Click Publish repository and untick Keep this code private.
  4. After each change: write a Summary → Commit to main → Push origin.
VS Code's Source Control buttons
  1. With Git installed, open your folder and click the Source Control icon in the left bar (Ctrl+Shift+G).
  2. First time: Initialize Repository → type a message → Commit → Publish Branch → Publish to GitHub public repository.
  3. After each change: type a message → Commit → Sync Changes.

Common problems

Push “rejected” / “Updates were rejected”

A teammate pushed something you don't have yet. Pull first, then push:

git pull --no-rebase --no-edit
git push
“CONFLICT” after pulling

You and a teammate changed the same lines. Open the file it names, find the part between <<<<<<< and >>>>>>>, keep the version you want, delete the marker lines, save, then run git add ., git commit -m "fixed conflict" and git push. VS Code shows buttons to pick a version, which makes this easier.

“Permission denied” or error 403 when pushing

You're signed in with a GitHub account that doesn't own the repo. Ask the owner to add you as a collaborator (step 3), and accept the invite email.

My push worked but the live site didn't change

Hosts take a minute or two to update. Check your host's deployments page, then refresh your site with Ctrl+Shift+R (Cmd+Shift+R on a Mac).

For setup errors (Git not found, wrong folder, signing in), see Common problems in the tab.

Vercel puts your site online for free and gives you a clean link like your-project.vercel.app. It reads your code from GitHub, so every time you update GitHub, your live site updates by itself.

The short version

  1. Push your code to GitHub (steps 1–5 in the GitHub tab)
  2. Sign up to Vercel with your GitHub account
  3. Import your repo
  4. Click Deploy
  5. Paste your .vercel.app link in the Submit form

1 Put your code on GitHub first

Vercel takes your code from a GitHub repository. If you haven't yet, follow steps 1–5 in the GitHub tab: make an account, create a repo and push your code from the terminal. You can skip GitHub Pages.

2 Create your Vercel account

  1. Go to vercel.com/signup.
  2. Choose the Hobby plan (it's free) and type your name.
  3. Click Continue with GitHub and sign in with the same GitHub account that has your repo.
  4. When GitHub asks, click Authorize Vercel.

Signing up with GitHub links the two accounts, so Vercel can see your repos. You don't need a separate password.

3 Import your repo

  1. On your Vercel dashboard, click Add New… → Project.
  2. Under Import Git Repository, find your repo and click Import.
  3. Don't see it? Click Adjust GitHub App Permissions (or Install), choose your account, give Vercel access to that repo and save. Then it appears in the list.

4 Deploy

  1. Project Name: this becomes your link, so keep it short, for example deadpool-job-board.
  2. Framework Preset: for a plain HTML/CSS/JavaScript site choose Other. If you used React or Vite, Vercel picks the right one for you.
  3. Leave Root Directory and the build settings as they are.
  4. Click Deploy and wait about a minute.
  5. When you see the congratulations screen, click Continue to Dashboard. Your link is under Domains, for example https://deadpool-job-board.vercel.app. Open it and check your site works.

5 Changed something? Update it

Just update your files on GitHub (Add file → Upload files → Commit changes). Vercel notices and puts the new version online within a minute or two. You don't need to touch Vercel again.

6 Submit your links

  • Live Hosted Website URL: your Vercel link, https://your-project.vercel.app
  • GitHub Repository URL: https://github.com/your-username/your-repo-name

Common problems

My link shows “404: NOT_FOUND”

Vercel can't find your main page. It must be named exactly index.html (all lowercase) and sit at the top of your repo. If it's inside a folder, open your project in Vercel → Settings → Build and Deployment → set Root Directory to that folder, then redeploy (or move the files to the top of the repo on GitHub).

My repo isn't in the import list

Vercel only sees repos you've given it access to. On the import page click Adjust GitHub App Permissions, pick your account, allow the repo and save. Also check you signed in to Vercel with the same GitHub account that owns the repo.

The deployment says “Build failed”

For a plain HTML/CSS/JavaScript site, open the project's Settings → Build and Deployment, set Framework Preset to Other, turn off any custom Build Command, save and redeploy. For React/Vite, open the failed deployment and read the red error lines. It's usually a missing file or a typo, and fixing it on GitHub redeploys automatically.

My changes aren't showing on the live site

Check that you clicked Commit changes on GitHub, then look at the Deployments tab in Vercel: the newest one should say Ready. Then press Ctrl+Shift+R (Cmd+Shift+R on a Mac) on your site.

Is it really free? Does everyone in the team need an account?

Yes, the Hobby plan is free. Only the person who owns the GitHub repo needs a Vercel account. Everyone else just uses the link.

Netlify can put your site online in two ways: drag and drop your folder (easiest, no GitHub needed), or connect your GitHub repo so it updates by itself.

1 Create your Netlify account

  1. Go to app.netlify.com/signup.
  2. Sign up with GitHub or with your email. The free plan is all you need.
  3. If it asks a few setup questions, answer them or skip them.

2 Easiest: drag and drop your folder

  1. On your Netlify dashboard, click Add new site (or Add new project) → Deploy manually.
  2. Drag your project folder (the folder that contains index.html) onto the box.
  3. Wait a few seconds. Your link appears at the top, for example https://random-name-123.netlify.app.
  4. To update it later: open your site in Netlify → Deploys → drag the folder onto the box again.

With drag and drop there's no GitHub repo, so for your code upload a .zip of your folder in the Submit form.

3 Or: connect your GitHub repo

  1. Push your code to GitHub first (steps 1–5 in the GitHub tab).
  2. Click Add new site → Import an existing project → GitHub, allow Netlify to access GitHub, and pick your repo.
  3. For a plain HTML/CSS/JavaScript site, leave Build command and Publish directory empty. For React/Vite, use npm run build and dist (Netlify usually fills these in).
  4. Click Deploy. From now on, every change you commit on GitHub goes live by itself.

Nicer link and common problems

How do I change the random link name?

Open your site in Netlify, go to its settings and look for Change site name. The name you choose becomes your-name.netlify.app.

My link says “Page not found”

Your main page must be called exactly index.html and sit at the top of the folder you dragged in (or the top of your repo). If you dragged a folder that only contains another folder, drag the inner one instead.

The design or images are missing

Capital letters matter online: Logo.png and logo.png are different. Use paths like images/logo.png, never C:\Users\....

Render hosts your site for free as a Static Site and gives you a link like your-project.onrender.com. It reads your code from GitHub.

1 Put your code on GitHub first

Follow steps 1–5 in the GitHub tab: make an account, create a repo and push your code from the terminal.

2 Create your Render account

  1. Go to dashboard.render.com/register.
  2. Choose GitHub to sign up, and allow Render to access your account.

3 Create a Static Site

  1. In your dashboard, click New (or + New) → Static Site.
  2. Pick your repo from the list and click Connect. If it's not there, click the link to configure GitHub access and allow that repo.
  3. Name: this becomes your link, for example deadpool-job-board.
  4. Branch: main.
  5. Build Command: leave it empty for plain HTML. For React/Vite use npm install && npm run build.
  6. Publish Directory: . (just a dot) for plain HTML. For Vite use dist.
  7. Click the button at the bottom to create and deploy the site, and wait 1–3 minutes.
  8. Your link appears near the top of the page, for example https://deadpool-job-board.onrender.com.

Every change you commit on GitHub redeploys your site by itself.

Common problems

Render won't let me leave Build Command empty

Type echo done as the build command. It does nothing, which is exactly what a plain HTML site needs.

My link says “Not Found”

Check the Publish Directory in the site's settings. It must be the folder that contains index.html: . if it's at the top of the repo. Then trigger a new deploy.

The deploy failed

Open the deploy's Logs and read the red lines. For plain HTML the usual cause is a build command that tries to run npm. Clear it (or use echo done) and redeploy.

Cloudflare Pages hosts your site for free with a link like your-project.pages.dev. You can upload your folder directly or connect GitHub.

1 Create your Cloudflare account

  1. Go to dash.cloudflare.com/sign-up, enter your email and a password, and verify your email.
  2. You don't need a domain name or a paid plan. Skip anything that asks you to add a website or domain.

2 Start a Pages project

  1. In the left menu open Workers & Pages (it may be inside Compute), then click Create.
  2. Choose Pages. If it shows Workers first, look for the Pages tab or a “Get started” link for Pages.

3 Easiest: upload your folder

  1. Choose Upload assets (drag and drop).
  2. Give your project a name. It becomes your-name.pages.dev. Click Create project.
  3. Drag your project folder (the one that contains index.html) onto the box, then click Deploy site.
  4. To update it later: open the project → Create deployment → drag the folder again.

With an upload there's no GitHub repo, so for your code upload a .zip of your folder in the Submit form.

4 Or: connect your GitHub repo

  1. Push your code to GitHub first (steps 1–5 in the GitHub tab).
  2. Choose Connect to Git (or Import an existing Git repository), connect your GitHub account, pick your repo and click Begin setup.
  3. Framework preset: None for plain HTML. Leave Build command and Build output directory empty. For React/Vite use npm run build and dist.
  4. Click Save and Deploy. Every change you commit on GitHub goes live by itself.

Common problems

My new link shows an error

A brand-new .pages.dev link can take a minute or two to start working. Wait, then refresh.

It says the page can't be found

Your main page must be called exactly index.html and sit at the top of the folder you uploaded (or the top of your repo).

Button names on these sites change now and then. If something looks a little different, look for the closest match. Still stuck? Ask any organiser. We're happy to help.
